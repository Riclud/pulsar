# Компоненты и сигналы

Pulsar обновляет только то, что изменилось. Рендер запоминает, что он прочитал, и
при изменении одного из этих значений запускается заново только он. На этой
странице объясняется, как этим пользоваться: где живёт состояние, как работают
компоненты и чего избегать.

## Главное правило

**Всё, что читает рендер, должно быть реактивным:** сигнал, `createState` или
`app.store`. Обычная переменная читается один раз и экран не обновляет.

```ts
let plain = 0
const count = signal(0)

app.window().render(() =>
  Column(
    {},
    Text({ text: String(plain) }), // не обновится
    Text({ text: String(count.get()) }), // обновится
  ),
)
```

## Где живёт состояние

| Состояние                              | Используйте   |
| -------------------------------------- | ------------- |
| Внутри одного компонента: поле, флажок | `signal`      |
| Общее для экранов приложения           | `createState` |
| Нужно QML или должно пережить reload   | `app.store`   |

### signal

```ts
const count = signal(0)

count.get() // прочитать и подписаться
count.set(1) // записать
count.peek() // прочитать без подписки
```

Запись того же значения ничего не делает. Сравнение идёт по ссылке, поэтому
создавайте новый массив или объект, а не меняйте существующий:

```ts
items.get().push(item) // экран не обновится
items.set([...items.peek(), item]) // обновится
```

### computed

Значение, вычисленное из других. Считается лениво и кэширует результат.

```ts
const open = computed(() => tasks.get().filter((task) => !task.done))

open.get()
```

### createState

Похожий на обычный объект, поля которого — сигналы. Это самый простой способ
хранить состояние приложения: чтение и запись остаются обычным кодом.

```ts
export const state = createState({
  tasks: [] as Task[],
  filter: "",
})

state.filter = "open"
state.tasks = [...state.tasks, task]
```

Отслеживается только присваивание поля верхнего уровня. `state.tasks.push(task)`
на экране ничего не изменит.

### effect

Выполняется сразу и снова после изменения всего, что прочитал. Возвращает функцию
остановки.

```ts
const stop = effect(() => {
  void storage.set("filter", state.filter)
})
```

Чтобы прочитать значение без подписки, используйте `untracked(() => ...)`.

### app.store

Store — та же идея со строковыми ключами. Каждый ключ отслеживается отдельно, а
значения публикуются ещё и в QML как `Store.<key>`, поэтому любое изменение идёт
через мост. Для состояния интерфейса, которое читает только JavaScript, лучше
подходят сигналы.

## Компоненты

Компонент — это функция, обёрнутая в `component`. Есть две формы.

**Простая.** Возвращает узел, и при изменении вся функция запускается заново.
Подходит для компонентов без локального состояния.

```ts
const Title = component<{ text: string }>(({ text }) => {
  return Text({ text, size: 20, weight: "semibold" })
})
```

**С настройкой.** Возвращает функцию рендера. Внешняя часть выполняется один раз
на инстанс, поэтому локальное состояние живёт в ней.

```ts
const Counter = component<{ label: string }>((props) => {
  const count = signal(0)

  return () => {
    return Button({
      label: `${props.label}: ${count.get()}`,
      onClick: () => count.set(count.peek() + 1),
    })
  }
})
```

Не создавайте сигнал в простой форме: он будет создаваться заново при каждом
запуске.

### В JSX

В файле `.tsx` все формы работают так же. Компонент получает свойства атрибутами, а
дети приходят как обычно. Настройка описана в разделе [JSX](../web/#jsx).

```tsx
const Counter = component<{ label: string }>((props) => {
  const count = signal(0)

  return () => (
    <Button onClick={() => count.set(count.peek() + 1)}>
      {`${props.label}: ${count.get()}`}
    </Button>
  )
})

<Counter label="Нажатия" />
```

### Свойства

Компонент запускается заново при изменении свойства, сравнение идёт по ссылке. Если
родитель перерисовался с равными свойствами, используется прошлый результат.

- **В форме с настройкой читайте через `props`.** Деструктуризация в настройке
  навсегда сохранит первое значение.
- **Новая функция не считается изменением**, поэтому `onClick: () => ...` не
  вызывает перерисовку ребёнка. Замыкание заменится только при его перерисовке,
  так что всё, от чего зависит колбэк, тоже должно быть свойством или сигналом.
- **Дети** приходят аргументами, а в форме с настройкой — ещё и как
  `props.children`. Компонент с детьми перерисовывается вместе с родителем.

### Ключи

Указывайте `key` у всего, что выводится из списка, как в React. Без него
идентичность определяется порядком вызовов, и вставка строки отдаст каждой строке
состояние её соседа.

```ts
Column({}, ...tasks.map((task) => TaskRow({ key: task.id, task })))
```

Два компонента с одинаковым ключом вызовут предупреждение.

### Жизненный цикл

```ts
const Clock = component(() => {
  const now = signal(Date.now())

  onMount(() => {
    const timer = setInterval(() => now.set(Date.now()), 1000)

    return () => clearInterval(timer)
  })

  onCleanup(() => console.log("removed"))

  return () => Text({ text: new Date(now.get()).toLocaleTimeString() })
})
```

`onMount` выполняется после того, как первый рендер дошёл до хоста. Возвращённая им
функция и `onCleanup` выполняются, когда компонент покидает дерево. Оба нужно
вызывать во время настройки.

## Сохранить экран

Обычно экран, покинувший дерево, уничтожается, и при следующем открытии строится
заново. `KeepAlive` строит содержимое при первом показе, а затем только скрывает его,
поэтому экран возвращается сразу, с той же позицией скролла и введённым текстом.

```ts
Stack(
  { fill: true },
  KeepAlive({ key: "list", active: !ui.calendarOpen }, () => ListScreen({})),
  KeepAlive({ key: "calendar", active: ui.calendarOpen }, () => CalendarScreen({})),
)
```

В JSX содержимое тоже функция:

```tsx
<KeepAlive active={ui.calendarOpen}>{() => <CalendarScreen />}</KeepAlive>
```

Содержимое передаётся функцией, чтобы до первого показа ничего не строилось. Скрытое
содержимое не перерисовывается: изменения запоминаются и применяются при следующем
показе, поэтому скрытый экран стоит памяти, но не времени. `KeepAlive` принимает
свойства `Box`, включая `enter`, `exit` и `transition` для плавного переключения, и по
умолчанию заполняет родителя. С `preload: true` содержимое строится заранее, поэтому и
первое открытие будет мгновенным.

- **Эффекты и таймеры продолжают работать.** Приостановлена только отрисовка, поэтому
  останавливайте то, что не нужно на скрытом экране.
- **Состояние сохраняется.** Не используйте его для формы, которая должна открываться
  пустой, например для редактора другой записи. Её рисуйте обычным условием.
- **Удаление освобождает всё.** Когда `KeepAlive` покидает дерево, содержимое
  уничтожается и выполняется `onCleanup`.

## Делайте обновления маленькими

Рендер запускается целиком, поэтому разбивайте экран по тому, что меняется вместе:

```ts
const Header = component(() => Text({ text: `Осталось: ${open.get().length}` }))
const List = component(() => Column({}, ...rows()))

app.window().render(() => Column({}, Header({}), List({})))
```

Теперь изменение одной строки не трогает шапку, а ввод в поиске перезапускает
только компоненты, читающие запрос.

Задайте `PULSAR_DEBUG=1`, чтобы видеть длительность каждого обновления, или читайте
её в коде:

```ts
app.onUiTimings = ({ build, send, patches }) => console.log(build, send, patches)
```

## Состояние вне реактивной системы

Если рендер зависит от того, что сигналы не видят, вызовите `app.invalidateUi()`,
чтобы перерисовать всё. Это крайняя мера.

## Переход со старых версий

Раньше любое изменение Store запускало рендер всего окна.

- Замените состояние на уровне модуля на `createState`.
- Замените `defineComponent` на `component`. Старое имя продолжает работать.
- `store.set` теперь сравнивает объекты по ссылке, так что запись равной копии
  считается изменением.
- `bind()` работает и читается при рендере своего компонента.
- `memo` работает, но не видит значений, прочитанных внутри компонента. Лучше
  использовать `component`.
- `fillWidth` и `fillHeight` всегда заполняют `Row` или `Column`; раньше они
  останавливались на размере детей.
- Раскладка со свободным местом держит детей в начале, а высокий `Box` больше не
  центрирует ребёнка. Используйте `Column({ justify: "center", alignItems: "center" })`.
- У окна нет своего отступа, поэтому задайте `padding` корневому узлу.
- `flickVelocity` и `flickDeceleration` удалены; `overscroll` теперь по умолчанию true.
